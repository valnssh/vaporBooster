# Более безопасная версия vaporBooster — v0.0.4

Основа: `valnssh/vaporBooster`, коммит `cc1e8f3b9179b70ca455cfdca63cabab3a550cfd`.

## Изменения

- В v0.0.4 уникальность Steam-логинов ограничена владельцем, с отдельным
  ограничением для общего локального режима. Чужая неподтверждённая попытка
  больше не блокирует добавление логина другим владельцем и не раскрывает,
  зарегистрировано ли это имя у другого пользователя панели.
  Новая миграция удаляет прежний общий индекс, сохраняя данные и регистр имён.
- Штатные журналы Steam-клиента и менеджера содержат общие сообщения событий,
  без Steam-логинов, внутренних ID аккаунтов и домена почты Steam Guard.
  Прежние файлы журналов и их копии автоматически не очищаются.

- Нативный HTTPS обязателен. Нет HTTP fallback; без сертификата и ключа сервер
  не запускается. Требуются совпадающие HTTPS `BETTER_AUTH_URL` и `ORIGIN`.
- Cookies авторизации всегда `Secure`; HSTS добавляется к ответам панели,
  статики и ошибок. Сертификаты исключены из Git, Docker build и Vite-раздачи.
- Для Steam включён `webCompatibilityMode`: библиотека выбирает только WSS
  на порту 443. Сырой TCP-транспорт исключён из входа по паролю/токену.

- Веб-панель получает только разрешённые поля аккаунта. Steam Guard seed,
  refresh token, IV/tag и полная auth-сессия не сериализуются в браузер.
- Все действия с аккаунтом проверяют владельца. Без OIDC доступны только
  аккаунты с `userId = null`, а общий режим требует явного `ALLOW_ANONYMOUS=true`.
- Частичная конфигурация OIDC и слабый master secret блокируют запуск.
- Подтверждения удаления выводятся как текст, без `@html` для пользовательских имён.
- QR-вход хранит владельца с момента создания, ограничен 16 сессиями на процесс
  и двумя на владельца, имеет TTL 120 секунд и отмену. События обрабатываются
  независимо от polling; результат можно потребить только один раз.
- В `patches/steam-session@1.9.4.patch` исправлена отмена незавершённого
  WebSocket-подключения библиотеки: отменённая попытка больше не переподключается.
  Собственный HTTPS agent каждой QR-сессии уничтожается при завершении.
- Новые токены и 2FA seeds шифруются AES-256-GCM с версионированием. Старые
  токены читаются прежним алгоритмом; plaintext seeds всех аккаунтов
  мигрируют при инициализации. Пароли Steam остаются временными аргументами входа.
- Повреждённый seed отклоняется только для своего аккаунта (`LOGIN_REQUIRED`),
  без блокировки панели и удаления других аккаунтов. Он не трактуется как plaintext.
- Удалены Google Fonts, интеграция SteamDB и вывод содержимого чата в stdout.
  Better Auth telemetry явно выключена. История чата по-прежнему хранится в БД
  для штатного интерфейса; доступ к БД и её резервным копиям нужно ограничивать.
- Зависимости обновлены и зафиксированы lockfile и точными версиями.
  Для старых транзитивных зависимостей Steam установлены целевые overrides;
  их используемые protobuf/ZIP API проверяются регрессионным тестом.
- Docker исключает приватные настройки, сертификаты и резервные копии из build
  context. Сборка не подключается к БД; SQL-миграции выполняются при запуске.
- Приложение хранит данные в PostgreSQL через TLS с проверкой сертификата.
  HoursBooster и Keycloak используют отдельные базы и ограниченные роли.
- Контейнер приложения работает как `deno`, без capabilities, с read-only root
  filesystem. У Deno нет `--allow-run`, FFI и разрешения на запись файлов.

## Запуск и обновление

Для новой установки используйте [полную инструкцию](DEPLOY_FULL_STACK.ru.md):
она описывает Docker, Nginx, PostgreSQL, Keycloak, сертификаты и первый вход.
Для обновлений и резервного копирования используйте [обслуживание](DEPLOY_MAINTENANCE.ru.md).
Сохраняйте прежний сильный `BETTER_AUTH_SECRET`: он нужен для чтения токенов.

Шифрование при обновлении не стирает прежний plaintext из резервных копий,
освобождённых страниц БД или снапшотов. Смена master secret требует отдельного
перешифрования либо повторного входа в аккаунты.

## Проверки и границы

`pnpm test` выполняет проверки с отдельными PostgreSQL-базами и подменёнными
Steam-клиентами. Учётные данные в тестах синтетические. Порядок запуска тестовой
БД, проверки типов, форматирования, сборки и Deno runtime указан в README.

CI проверяет Linux-образы, полную Compose-установку, HTTPS, настоящий Keycloak
OIDC/PKCE, Secure cookies, TLS и изоляцию ролей PostgreSQL, восстановление обеих БД.
Тесты не доказывают отсутствия уязвимостей. Вход в Steam для бустинга требует
отдельной проверки с разрешённым тестовым аккаунтом.

Приложению необходим исходящий доступ к Steam, DNS и настроенным OIDC/DB.
Разрешение `--allow-net` не является списком допустимых адресов. Контейнерные
ограничения не заменяют контроль трафика, защиту дисков и резервных копий,
а также проверку образов перед публичным развёртыванием.
