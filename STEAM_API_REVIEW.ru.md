# Проверка интеграции Steam — 30 октября 2026

## Дополнение v0.0.2: шифрование передачи

Веб-вход принимает только HTTPS, включая localhost. Порт HTTP отсутствует.
Проверены отказ обычному HTTP, проверка сертификата и имени сервера,
Secure/HttpOnly/SameSite cookies, HSTS и отсутствие выдачи приватных файлов.

Для `steam-user` включён `webCompatibilityMode`: выбор серверов ограничен
WebSocket TLS на порту 443, без перехода на сырой TCP. Обнаруженный в библиотеке
риск обхода обычного TCP-рукопожатия исключён из используемого пути.
При отсутствии подходящего защищённого сервера вход завершается ошибкой,
а не переключается на TCP. Тест использует настоящий выбор транспорта библиотеки
с подменённым каталогом серверов и без сетевого обмена учётными данными.

Пароль и Steam Guard code отправляются через тот же WSS-транспорт; пароль также
шифруется RSA в штатной библиотеке авторизации. Shared secret остаётся на сервере
и используется для вычисления одноразового кода. Повторный вход с refresh token
и QR-авторизация используют WSS. В настоящем Deno проверено, что библиотека
WebSocket отклоняет неизвестный CA и неверное имя сертификата, а корректная
проверенная TLS-сессия работает. Отключение проверки сертификатов не используется.

Сохранённые Steam refresh tokens и shared secrets зашифрованы AES-256-GCM.
Пароль не сохраняется в базе. Сервер обрабатывает пароль/коды/токены в памяти,
чтобы выполнить авторизацию; HTTPS не скрывает их от самого сервера и Steam.
Это транспортное шифрование, а не сквозное шифрование против владельца сервера.
Реальные пароли и подтверждённый вход в аккаунт в тестах не использовались.

Материалы исходных библиотек:
[SteamUser: webCompatibilityMode](https://github.com/DoctorMcKay/node-steam-user#webcompatibilitymode),
[Steam Session](https://github.com/DoctorMcKay/node-steam-session).

Ниже сохранены результаты проверки предыдущей версии; актуальные HTTPS-настройки
описаны в `DEPLOY_DEBIAN13.ru.md` и `CHANGELOG.md`.

Проверены только используемые вызовы в `client.ts`, `manager.ts` и `session_store.ts`,
их вызывающие обработчики и исходники установленных библиотек. Приложение работает
через клиентский протокол Steam и авторизацию Steam; ключ публичного Web API для
текущих функций не требуется. Это сторонние библиотеки, а не официальный SDK Valve.

## Проверки и границы результата

- 22 автоматические проверки: прежние проверки безопасности и 9 новых проверок Steam.
  В тестах входа используется настоящий steam-user с отключённым сетевым транспортом;
  проверки очереди используют настоящие PostgreSQL и шифрование с подменённым клиентом.
- Проверены типы, форматирование и production build.
- Исправлена раздача статических файлов в Windows: адаптер терял параметр имени
  файла при преобразовании `/` в `\`. Проверка `pnpm test:runtime` получила HTTP 200
  для 5 CSS и 11 JavaScript-модулей с корректными MIME-типами, а также favicon.
  Приватные пути и проверенные варианты обхода пути не выдают содержимое файлов.
- В настоящем Deno production-процессе получен живой QR challenge Steam (`s.team`),
  проверены ожидание, отмена и HTTP 404 после отмены. QR и токены не включены в журнал.
- Настоящий пароль, сканирование QR, доставка сообщения и начисление часов не проверялись.
  Тесты не подтверждают фактическое начисление часов.
- Фиксированного списка IP нет: клиентские серверы обнаруживаются через Steam Directory.
  Полученный живой список содержал 51 сервер; один из WebSocket-адресов находился в
  домене `steamserver.net`. Этот результат не является полным перехватом трафика.
- Контейнерная сборка и Linux-запуск пока не проверены.
- Minimus сообщил об отключении своего реестра 22 октября 2026:
  [официальное объявление](https://www.minimus.io/get-started).
  Dockerfile не переведён на недоступный реестр; текущие закреплённые базы сохранены.

Настройки продления refresh tokens оставлены штатными: принудительное обновление
инвалидирует прежний токен, поэтому оно не включалось без отдельной необходимости.
