# Перенос SQLite → PostgreSQL

Новая версия хранит все данные HoursBooster в PostgreSQL. Keycloak использует
свою отдельную БД и роль. Импорт переносит пользователей, сессии, привязки,
Steam-аккаунты, настройки и всю переписку. Идентификаторы, даты и шифротекст
сохраняются; `BETTER_AUTH_SECRET` менять нельзя.

Импорт читает SQLite только для чтения, проверяет целостность, переносит данные
одной транзакцией и сверяет содержимое каждой записи. Непустая целевая БД,
повторный импорт и неизвестные таблицы/столбцы отклоняются. При ошибке
вставленные записи откатываются. SQLite-зависимостей в рабочем приложении нет;
старые SQL-миграции в `drizzle/sqlite` оставлены для проверки совместимости.

## Полная установка Docker Compose

Все команды — из корня существующего репозитория. Сначала остановите старую
версию, пока её Compose-файл ещё на месте. Другие операции с аккаунтами на время
переноса исключите. Не запускайте старую и новую версии одновременно.

```bash
dc() { sudo docker compose --project-name hoursbooster --env-file .private/full-stack/compose.env -f deploy/full-stack/compose.yml "$@"; }
dc stop vaporbooster
umask 077
backup="backups/before-postgresql-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$backup"
sudo mkdir -p .private/full-stack/sqlite-backup
dc cp vaporbooster:/data/. .private/full-stack/sqlite-backup
sudo cp -a .private/full-stack "$backup/private"
dc exec -T postgres pg_dumpall -U postgres > "$backup/postgres.sql"
git pull --ff-only
```

Копируйте **весь** каталог `/data`, включая `-wal`/`-shm`, а не только `.db`:
последние сообщения могут находиться в журнале. Каталог резервных копий содержит
секреты: храните его закрытым и зашифрованным, не загружайте в Git/issue.

Если раньше использовался Caddy, подготовьте сертификат на оба домена в
`certs/full-stack/nginx` по [инструкции установки](DEPLOY_FULL_STACK.ru.md).
Старые настройки `SERVER_IP`/`ACME_EMAIL` установщик принимает для совместимости;
публичные сертификаты выпускает и продлевает внешний Certbot.

```bash
sudo python3 deploy/full-stack/setup.py --settings .private/full-stack/settings.env --prepare-only
dc up -d --build --wait --wait-timeout 120 postgres
dc exec -T postgres sh /docker-entrypoint-initdb.d/20-hoursbooster.sh
dc build vaporbooster sqlite-import proxy
dc run --rm --no-deps sqlite-import --source /input/sqlite.db --confirm-stopped
```

В отчёте должны появиться `committed and verified` и количества записей всех
шести таблиц. При ошибке **не запускайте приложение**: сохраните исходную копию,
проверьте целевую БД, TLS и совместимость старой схемы. Импорт не очищает БД
и не пропускает неподдерживаемые данные. Если файл раньше назывался иначе,
замените `sqlite.db` его именем внутри скопированного каталога.
При нестандартном имени задайте приложению `LEGACY_SQLITE_FILE` с путём к старому
файлу внутри контейнера (например `/data/old-name.db`), чтобы защитная проверка
также обнаруживала его. В полной схеме это можно добавить в приватный Compose override.

```bash
dc up -d --no-deps --force-recreate vaporbooster proxy
dc ps
```

Проверьте вход в панель, владельцев аккаунтов, настройки и историю. Старая версия
при штатном завершении могла сохранить аккаунты как `IDLE`; при необходимости
нажмите Start. Новая версия сохраняет активное состояние при штатном завершении
и восстанавливает его после запуска. Старый том остаётся подключён только для
чтения; наличие неперенесённого `/data/sqlite.db` блокирует запуск с пустой БД.

Для повторной проверки используйте отдельную пустую тестовую БД. Не удаляйте
маркер импорта и не очищайте рабочие таблицы ради повторного запуска.

## Установка без полного Compose

Нужны Node.js 24, зависимости проекта и отдельная пустая PostgreSQL-БД,
принадлежащая выделенной роли без `SUPERUSER`, `CREATEDB`, `CREATEROLE`.
В приватном `.env` задайте `DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DB`
(спецсимволы пароля кодируются для URL) и `DATABASE_CA_FILE=/путь/ca.pem`, если
сервер использует частный CA. TLS и проверка имени сервера обязательны;
параметры `sslmode` в URL не используются. Для публичного CA переменную пути
можно не задавать: используются доверенные корневые сертификаты системы.

После остановки старого приложения и согласованного копирования SQLite:

```bash
pnpm install --frozen-lockfile --ignore-scripts
pnpm import:sqlite --source /закрытый/каталог/sqlite.db --confirm-stopped
pnpm build
pnpm start
```

## Откат

До появления новых записей в PostgreSQL можно остановить новую версию и
восстановить прежний выпуск с исходной SQLite и тем же ключом. После начала
работы PostgreSQL простой запуск старой SQLite потеряет изменения, сделанные
после переноса: сначала сохраните обе БД и подготовьте согласованный перенос
этих изменений. Обратный автоматический импорт в SQLite не предусмотрен.
